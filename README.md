# TaskReady

Команда R2C: ddigreen и saimonset. Репозиторий: [BAITC-Hacks/hack-4fa785fd-r2c](https://github.com/BAITC-Hacks/hack-4fa785fd-r2c).

Каркас веб-MVP HackAlem AI по кейсу AI Sana «Рейтинг качества бизнес-задач и открытый выбор команд». Источник требований — [AGENTS.md](AGENTS.md). Интерфейс на русском.

## Текущий результат

Это основа для дальнейшей совместной разработки, а не завершённый сквозной MVP.

Готово:

- Next.js App Router, TypeScript strict, Tailwind CSS и локальные компоненты shadcn/ui.
- Все семь страниц из задания, навигация и переключение демонстрационной роли через cookie.
- Каталог с фильтрами, карточки задач и отправка отклика через форму. Локальный мастер с редактированием, подтверждением полей и расчётом рейтинга.
- Общий контракт `lib/types.ts`: доменные типы, Zod-схемы API/LLM/хранилища/роли, JSON Schema для structured outputs.
- Детерминированная формула рейтинга, уровни, пояснения и рекомендации по совпадениям навыков и интересов.
- JSON-хранилище с инициализацией из seed, общей очередью записи, атомарной заменой файла и командой сброса.
- Пять черновиков, пять опубликованных задач всех четырёх уровней, пять команд и пять откликов. Данные синтетические.
- API каталога, команд и откликов; создание, редактирование и публикация задач, решения бизнеса по откликам и начисление баллов.
- AI API: OpenAI → NVIDIA NIM → локальная заглушка, JSON Schema structured outputs, Zod, проверка цитат и журнал всех попыток в базе.
- 3–6 уточняющих вопросов по весам недостающих полей, поддержка русского, казахского и английского.
- Компонент `AiDebugPanel` для отображения журнала AI API; текущий мок-мастер его не подключает.
- Мастер `/business/new`: мок-вопросы, редактирование и подтверждение каждого поля, живой рейтинг и расшифровка.
- Каталог с фильтрами, рекомендациями, карточкой задачи и сохранением отклика через POST API.
- Vitest для рейтинга, уровней, контракта, seed, хранилища, AI-провайдеров, цитат и API.

Заглушки и следующий этап:

- Мастер пока использует локальные моки анализа и не сохраняет задачу. Нужно подключить AI API, сохранение, публикацию и debug-журнал; действия кабинета бизнеса по редактированию и обработке откликов также требуют подключения.
- Локальная заглушка извлекает явно подписанные строки (`Данные: ...`, `Критерии успеха: ...`) и переносит ответы дословно. Остальные сведения остаются `null`; вопросы выбираются по пробелам. В debug указан `provider: "local"`.

## Установка и запуск

Нужен Node.js 20.9+ (рекомендуется актуальная LTS-версия) и npm. Установка зависимостей требует сети. Для запуска каркаса API-ключи не нужны.

```bash
npm install
npm run dev
```

Откройте адрес, напечатанный Next.js, обычно `http://localhost:3000`. `predev` создаёт `data/db.json` из `data/seed.json`, если базы ещё нет. Повторный запуск не сбрасывает изменения. Если порт занят, Next.js может выбрать другой.

Dev-скрипт включает опрос файлов раз в секунду (`WATCHPACK_POLLING=1000`), чтобы избежать ошибки `EMFILE` в ограниченных средах. Для стандартного наблюдения можно задать `WATCHPACK_POLLING=false`. Автогенерация правил Next.js отключена: исходный `AGENTS.md` сохраняется без изменений.

```bash
npm run reset
npm test
npm run lint
npm run typecheck
npm run build
npm start
```

`reset` **заменяет текущую локальную базу сидом**, включая очистку debug-журнала. Перед сбросом остановите dev-сервер, если с данными сейчас работают другие вкладки. Исходный `data/seed.json` не меняется.

Для подключения моделей скопируйте `.env.example` в `.env.local` и заполните ключ и идентификатор модели для нужного провайдера: `OPENAI_API_KEY` + `OPENAI_MODEL`, `NVIDIA_API_KEY` + `NVIDIA_MODEL`. OpenAI-модель должна поддерживать Responses API, JSON Schema structured outputs и `reasoning.effort: "low"`; NVIDIA-модель — NIM structured generation через `nvext.guided_json`. Адрес NVIDIA NIM: `https://integrate.api.nvidia.com/v1`. Перезапустите сервер после изменения окружения.

Оба провайдера необязательны. Без ключей сразу используется локальная заглушка. Ключ без имени модели записывает ошибку конфигурации в журнал и переводит запрос к следующему провайдеру. `.gitignore` исключает все `.env*`, кроме пустого шаблона `.env.example`.

## Формула рейтинга

Рейтинг вычисляет код, а не модель. Засчитываются только подтверждённые поля: заполненность определяется после trim, минимум 15 символов. Блоки имеют веса 20/20/15/15/10/10/10, точные проверки заданы в `AGENTS.md` и `lib/scoring.ts`. `potential` показывает результат при подтверждении всех заполненных полей. `title` баллов не даёт; для публикации требуется непустое название после trim.

`total` — сумма баллов пройденных проверок, максимум 100. Все проверки ниже требуют подтверждения соответствующего поля и не менее 15 символов после `trim`, включая контакт. Дополнительные проверки суммируются с баллами за заполненность.

| Блок (`key`) | Максимум | Проверки из `lib/scoring.ts` |
| --- | ---: | --- |
| Контекст и потребность (`contextNeed`) | 20 | `context` заполнен — 6; `need` заполнен — 6; длина `context` ≥ 80 — 4; длина `need` ≥ 60 — 4 |
| Данные и материалы (`data`) | 20 | Поле заполнено — 10; найден тип или источник из словаря `DATA_WORDS` (например CSV, Excel, JSON, SQL, API, таблица, CRM) — 5; есть цифра, обозначающая объём или период — 5 |
| Ожидаемый результат (`expectedResult`) | 15 | Поле заполнено — 9; найден артефакт из `ARTIFACT_WORDS` (например прототип, бот, дашборд, отчёт, приложение, API, MVP) — 6 |
| Критерии успеха (`successCriteria`) | 15 | Поле заполнено — 8; есть цифра, `%` или маркер измеримости: «не менее», «до», «сократить», «увеличить» и предусмотренные кодом аналоги на казахском/английском — 7 |
| Ограничения (`constraints`) | 10 | Поле заполнено — 5; найден срок из `TIME_WORDS`, технология/доступ из `TECH_OR_ACCESS_WORDS` или дата с разделителем `-`, `.` либо `/` — 5 |
| Пользователи (`users`) | 10 | Поле заполнено — 6; длина ≥ 40, есть цифра или роль из `USER_ROLE_WORDS` — 4 |
| Связь с бизнесом (`businessLink`) | 10 | `contact` содержит email, телефон минимум из 7 цифр или Telegram `@username` из 5–32 латинских букв, цифр и подчёркиваний — 5; `interactionFormat` заполнен — 3; в нём есть формат/частота из `FEEDBACK_WORDS`, «раз в», `every` или `рет` — 2 |

Словари проверяются без учёта регистра, по словам и их началам; поддерживаются русский, казахский и английский. Числа, длины и ключевые слова проверяются формально: код не проверяет смысл или достоверность текста. Полный источник условий — [lib/scoring.ts](lib/scoring.ts).

`missing` содержит все непройденные проверки, отсортированные по убыванию баллов, с подсказками «+N баллов». В мастере изменение поля сбрасывает его подтверждение и сразу пересчитывает рейтинг. `potential` пересчитывается по тем же правилам, но без требования подтверждения.

| Баллы | Уровень | Отображение |
| --- | --- | --- |
| 0–39 | `draft` | Черновик · требует уточнения |
| 40–69 | `workable` | Рабочая |
| 70–89 | `ready` | Готовая |
| 90–100 | `priority` | Приоритетная |

## Правила каталога

Уровень `draft` не равен статусу неопубликованной задачи. Каталог показывает **все опубликованные задачи любого уровня**; неопубликованные задачи со статусом `draft` в него не входят.

GET `/api/tasks` возвращает все опубликованные задачи, включая низкий рейтинг. Сортировка по баллу по убыванию, затем более новые выше. Фильтры: `industry` и `level`. Параметр `teamId` добавляет отдельный список `recommended`, не ограничивая основной каталог. Рекомендации только для `workable` и выше.

- При равенстве баллов сравнивается `publishedAt`, а если его нет — `createdAt`.
- Уровень `priority` визуально выделен; `draft` помечен «требует уточнения». Низкий рейтинг не запрещает отклик.
- Для выбранной команды рекомендации показываются отдельно с объяснением совпадений интересов, навыков или технологий с отраслью и тегами задачи. Персональные и чувствительные признаки не используются.
- На `/catalog/[id]` показываются подтверждённые поля и форма отклика: команда, идея, план, срок, ссылка на прототип (`http://` или `https://`). Отклик сохраняется со статусом `pending`.
- Команды выбирает бизнес вручную; автоматического назначения нет.
- По требованиям после публикации должна появляться позиция «Ваша задача на N месте из M». API публикации возвращает позицию; мастер и этот экран пока не подключены к API.

Действия бизнеса через API: принять одну, несколько или ни одной команды; отклонить отклик; подтвердить этап принятого отклика и однократно начислить команде +50. Эти операции реализованы в API; интерфейс бизнеса пока не подключён.

## API задач и откликов

- POST `/api/tasks`: создаёт `draft`, вычисляет `score`, добавляет первую запись `scoreHistory`; возвращает Task и HTTP 201.
- PATCH `/api/tasks/:id`: полностью заменяет `card`, пересчитывает `score` и дописывает `scoreHistory`; возвращает Task.
- POST `/api/tasks/:id/publish`: без тела, требует непустой `card.title.value`; возвращает поля Task плюс `position` (с 1) и `total` по всему опубликованному каталогу. Низкий рейтинг не блокирует публикацию. Повтор сохраняет исходный `publishedAt`.
- POST `/api/tasks/:id/proposals`: только для опубликованной задачи и существующей команды; возвращает Proposal и HTTP 201. Количество откликов не ограничено, включая повторные отклики одной команды.
- PATCH `/api/proposals/:id`: `accept` или `reject` меняют статус только выбранного отклика; можно принять несколько команд. `confirmMilestone` доступен только для `accepted` и один раз, команде начисляется +50. Повторное подтверждение возвращает HTTP 400; смена статуса не сбрасывает флаг начисления.

Входы проверяются существующими Zod-схемами. Ошибки формата и бизнес-правил возвращают `400 { error: string }`, отсутствующие задача/отклик/команда — 404, ошибка сохранения — 500. Проверки и изменения выполняются внутри одной очереди `updateDb`, включая защиту от двух одновременных начислений. Страницы мастера и действий бизнеса пока требуют подключения к API.

## AI API

POST `/api/ai/analyze` принимает `{ draftText, industry }`, возвращает `{ extracted, missing, questions, debug }`. Неизвестные поля отсутствуют в публичном `extracted`, перечисляются в `missing`; внутри structured output все ключи обязательны и допускают `null`.

POST `/api/ai/build-card` принимает `{ draftText, answers: [{ questionId, field, answer }] }`, возвращает `{ card, debug }`. В `card` присутствуют все десять полей, каждое — `{ value, evidence }` или `null`. Ответы могут быть пустым массивом. Последний ответ по полю имеет приоритет. Эти endpoint не создают бизнес-задачу и не подтверждают поля за человека.

Оба endpoint валидируют входы и выходы через Zod. Невалидный вход возвращает HTTP 400 с `error`. У каждой внешней попытки таймаут 12 секунд; сетевые ошибки, отказ провайдера и таймаут переключают провайдера сразу. Невалидные JSON/схема или обрезанный ответ повторяются один раз у того же провайдера. Максимум — четыре внешние попытки, затем локальная заглушка. Автоматические повторы SDK отключены. Для OpenAI используются Responses API, `reasoning.effort: "low"` и модель из `OPENAI_MODEL`, без `temperature` и `top_p`. Для NVIDIA остаётся Chat Completions с `temperature: 0.1`, `top_p: 1` и моделью из `NVIDIA_MODEL`.

`evidence` должна входить в один исходный текст (черновик или отдельный ответ), с нормализацией регистра и пробелов. Дополнительно `value` должен совпадать с цитатой целиком после такой же нормализации: нельзя прикрепить к цитате выдуманное значение или удалить из неё отрицание. Неподтверждённые источником поля отбрасываются и записываются как `rejected_unsupported`; никакие баллы ИИ не вычисляет. Проверка подтверждает происхождение цитаты, но не заменяет проверку её смысла человеком перед публикацией. Для анализа отрасль помогает задать вопросы, но не служит источником фактов о задаче.

Каждая попытка записывается в `data/db.json → aiLogs`, включая неудачи и локальный ответ. `debug` в API относится к итоговому провайдеру; вся цепочка доступна в `aiLogs`. Компонент `AiDebugPanel` пока не подключён к мок-мастеру. Общий префикс `id` связывает попытки одного запроса. Значения настроенных API-ключей маскируются в журнале. Ошибка сохранения журнала возвращает HTTP 500 и не запускает дополнительный внешний запрос.

Для быстрой проверки без ключей:

```bash
curl -sS http://localhost:3000/api/ai/analyze \
  -H 'Content-Type: application/json' \
  -d '{"draftText":"Клиенты стали реже возвращаться, хотим понять почему","industry":"Общепит"}'

curl -sS http://localhost:3000/api/ai/build-card \
  -H 'Content-Type: application/json' \
  -d '{"draftText":"Данные: Есть CSV с 1200 заказами за 6 месяцев","answers":[{"questionId":"q-result","field":"expectedResult","answer":"Нужен дашборд повторных покупок"}]}'
```

## Тестовые сценарии

### Пошаговый демо-сценарий из AGENTS.md

Это целевой сценарий из [AGENTS.md](AGENTS.md). Сейчас мастер работает на моках без сохранения; каталог и отправка отклика работают с локальной JSON-базой. Публикация, выбор команд и начисление баллов реализованы в API, но пока не подключены к интерфейсу.

1. Выберите роль «Бизнес: Кофейня \"Дала\"», откройте `/business/new` и введите: «Клиенты стали реже возвращаться, хотим понять почему и что с этим сделать». Ожидаемый начальный уровень — «Черновик»; без подтверждений баллы равны 0.
2. Нажмите «Уточнить задачу», ответьте на вопросы, соберите карточку. Отредактируйте и подтвердите поля по отдельности. Цель демо — довести рейтинг до «Готовая» (70–89). В текущей версии вопросы моковые; недостающие сведения нужно внести вручную, трёх ответов недостаточно для гарантированного достижения уровня.
3. Добавьте измеримый критерий успеха, например «Сократить время обработки заявки на 30%», и заново подтвердите поле. Цель — «Приоритетная» (90–100). Добавление измеримости даёт +7 к уже заполненному и подтверждённому критерию; для перехода с 83 до 90 остальные проверки должны давать 83 балла.
4. Опубликуйте задачу и проверьте сообщение «Ваша задача на N месте из M». **Пока недоступно:** мастер не сохраняет и не публикует карточку.
5. Переключитесь на роль команды, откройте `/catalog`, изучите рекомендации и отправьте отклик с идеей, планом, сроком и ссылкой. **Доступно сейчас для опубликованных задач из seed**; новая карточка из мастера в каталог пока не попадает.
6. Вернитесь в роль бизнеса: примите один отклик, отклоните другой, подтвердите этап принятого отклика. Ожидается однократное начисление команде +50 и обновление `/teams`. **Пока недоступно:** обработка откликов и начисление баллов не подключены.

### Проверка бизнеса и каталога сейчас

1. В мастере заполните поле, проверьте отсутствие баллов без подтверждения, подтвердите его и проверьте рост рейтинга. Измените текст: подтверждение должно сброситься, рейтинг — пересчитаться.
2. Откройте `/catalog`: баллы идут по убыванию, при равенстве выше более новая публикация. Проверьте каждый уровень и сочетание фильтров отрасли и уровня; при отсутствии совпадений должно появиться сообщение.
3. Выберите `draft`: опубликованные задачи низкого уровня должны остаться доступными. Откройте одну из них — форма отклика должна быть доступна. Выберите `priority` и проверьте визуальное выделение.
4. Выберите команду в шапке: рекомендации должны содержать причины совпадений и задачи не ниже `workable`; полный каталог остаётся доступным.
5. Отправьте заполненную форму с корректной HTTP(S)-ссылкой: ожидается «Отклик отправлен» и новая запись в локальной базе. Пустые обязательные поля или неверная ссылка должны препятствовать отправке. Эта проверка создаёт реальный локальный отклик.

### Проверка каркаса и API

1. Запустите проект без `.env.local` и откройте все семь страниц через навигацию.
2. Переключите роль на команду и обновите страницу: выбор должен сохраниться в cookie.
3. Откройте `/api/tasks` и `/api/teams`: должны возвращаться данные seed.
4. Выполните примеры AI API выше. Без ключей ожидаются 3–6 вопросов, поля с точными цитатами и debug с `provider: "local"`. Проверьте `debug` в ответе API и журнал `aiLogs` в локальной базе.
5. Отправьте пустой JSON в этот endpoint: ожидается HTTP 400 с полем `error`.
6. Запустите `npm test`: проверяются формула, границы, подтверждения, seed, параллельная запись и сохранность повреждённой базы, evidence, приоритет вопросов, таймауты, повторы, fallback и ответы API. Внешние вызовы в тестах заменены моками; тесты не используют ключи, сеть или рабочую базу.
7. Для возврата к демо-данным выполните `npm run reset`: локальная база должна совпасть с seed.

Полный бизнес-сценарий из `AGENTS.md` станет доступен после следующего этапа разработки. Развёрнутой версии пока нет.
