# TaskReady

Команда R2C: ddigreen и saimonset. Репозиторий: [BAITC-Hacks/hack-4fa785fd-r2c](https://github.com/BAITC-Hacks/hack-4fa785fd-r2c).

Каркас веб-MVP HackAlem AI по кейсу AI Sana «Рейтинг качества бизнес-задач и открытый выбор команд». Источник требований — [AGENTS.md](AGENTS.md). Интерфейс на русском.

## Текущий результат

Это основа для дальнейшей совместной разработки, а не завершённый сквозной MVP.

Готово:

- Next.js App Router, TypeScript strict, Tailwind CSS и локальные компоненты shadcn/ui.
- Все семь страниц из задания, навигация и переключение демонстрационной роли через cookie.
- Общий контракт `lib/types.ts`: доменные типы, Zod-схемы API/LLM/хранилища/роли, JSON Schema для structured outputs.
- Детерминированная формула рейтинга, уровни, пояснения и рекомендации по совпадениям навыков и интересов.
- JSON-хранилище с инициализацией из seed, общей очередью записи, атомарной заменой файла и командой сброса.
- Пять черновиков, пять опубликованных задач всех четырёх уровней, пять команд и пять откликов. Данные синтетические.
- GET API каталога, команд и откликов.
- AI API: OpenAI → NVIDIA NIM → локальная заглушка, JSON Schema structured outputs, Zod, проверка цитат и журнал всех попыток в базе.
- 3–6 уточняющих вопросов по весам недостающих полей, поддержка русского, казахского и английского.
- Панель «Как работает ИИ» на `/business/new`: провайдер, промпт, вход, сырой ответ, ошибки валидации и отброшенные поля.
- Vitest для рейтинга, уровней, контракта, seed, хранилища, AI-провайдеров, цитат и API.

Заглушки и следующий этап:

- Мастер, редактирование, публикация, отправка и обработка откликов, подтверждение этапов пока представлены страницами-заглушками.
- Изменяющие бизнес-данные API проверяют входы и возвращают `501 { error: string }`. Невалидные входы возвращают `400 { error: string }`.
- Локальная заглушка извлекает явно подписанные строки (`Данные: ...`, `Критерии успеха: ...`) и переносит ответы дословно. Остальные сведения остаются `null`; вопросы выбираются по пробелам. В debug указан `provider: "local"`.

## Установка и запуск

Нужен Node.js 20.9+ (рекомендуется актуальная LTS-версия) и npm. Установка зависимостей требует сети. Для запуска каркаса API-ключи не нужны.

```bash
npm ci
npm run dev
```

Откройте адрес, напечатанный Next.js, обычно `http://localhost:3000`. `predev` создаёт `data/db.json` из `data/seed.json`, если базы ещё нет. Повторный запуск не сбрасывает изменения. Если порт занят, Next.js может выбрать другой.

Dev-скрипт включает опрос файлов раз в секунду (`WATCHPACK_POLLING=1000`), чтобы избежать ошибки `EMFILE` в ограниченных средах. Для стандартного наблюдения можно задать `WATCHPACK_POLLING=false`. Автогенерация правил Next.js отключена: исходный `AGENTS.md` сохраняется без изменений.

```bash
npm run reset
npm test
npm run lint
npm run typecheck
npm run build
npm start
```

`reset` **заменяет текущую локальную базу сидом**, включая очистку debug-журнала. Перед сбросом остановите dev-сервер, если с данными сейчас работают другие вкладки. Исходный `data/seed.json` не меняется.

Для подключения моделей скопируйте `.env.example` в `.env.local` и заполните ключ и идентификатор модели для нужного провайдера: `OPENAI_API_KEY` + `OPENAI_MODEL`, `NVIDIA_API_KEY` + `NVIDIA_MODEL`. OpenAI-модель должна поддерживать JSON Schema structured outputs и `temperature`; NVIDIA-модель — NIM structured generation через `nvext.guided_json`. Адрес NVIDIA NIM: `https://integrate.api.nvidia.com/v1`. Перезапустите сервер после изменения окружения.

Оба провайдера необязательны. Без ключей сразу используется локальная заглушка. Ключ без имени модели записывает ошибку конфигурации в журнал и переводит запрос к следующему провайдеру. `.gitignore` исключает все `.env*`, кроме пустого шаблона `.env.example`.

## Рейтинг и правила каталога

Рейтинг вычисляет код, а не модель. Засчитываются только подтверждённые поля: заполненность определяется после trim, минимум 15 символов. Блоки имеют веса 20/20/15/15/10/10/10, точные проверки заданы в `AGENTS.md` и `lib/scoring.ts`. `potential` показывает результат при подтверждении всех заполненных полей. `title` баллов не даёт; при реализации публикации он должен быть обязателен.

Уровни: 0–39 `draft`, 40–69 `workable`, 70–89 `ready`, 90–100 `priority`. Уровень `draft` не равен статусу неопубликованной задачи.

GET `/api/tasks` возвращает все опубликованные задачи, включая низкий рейтинг. Сортировка по баллу по убыванию, затем более новые выше. Фильтры: `industry` и `level`. Параметр `teamId` добавляет отдельный список `recommended`, не ограничивая основной каталог. Рекомендации только для `workable` и выше.

Планируемые действия бизнеса: принять одну, несколько или ни одной команды; отклонить отклик; подтвердить этап принятого отклика и однократно начислить команде +50. Эти операции ещё не реализованы.

## AI API

POST `/api/ai/analyze` принимает `{ draftText, industry }`, возвращает `{ extracted, missing, questions, debug }`. Неизвестные поля отсутствуют в публичном `extracted`, перечисляются в `missing`; внутри structured output все ключи обязательны и допускают `null`.

POST `/api/ai/build-card` принимает `{ draftText, answers: [{ questionId, field, answer }] }`, возвращает `{ card, debug }`. В `card` присутствуют все десять полей, каждое — `{ value, evidence }` или `null`. Ответы могут быть пустым массивом. Последний ответ по полю имеет приоритет. Эти endpoint не создают бизнес-задачу и не подтверждают поля за человека.

Оба endpoint валидируют входы и выходы через Zod. Невалидный вход возвращает HTTP 400 с `error`. У каждой внешней попытки таймаут 12 секунд; сетевые ошибки, отказ провайдера и таймаут переключают провайдера сразу. Невалидные JSON/схема или обрезанный ответ повторяются один раз у того же провайдера. Максимум — четыре внешние попытки, затем локальная заглушка. Автоматические повторы SDK отключены. Температура — 0.1.

`evidence` должна входить в один исходный текст (черновик или отдельный ответ), с нормализацией регистра и пробелов. Дополнительно `value` должен совпадать с цитатой целиком после такой же нормализации: нельзя прикрепить к цитате выдуманное значение или удалить из неё отрицание. Неподтверждённые источником поля отбрасываются и записываются как `rejected_unsupported`; никакие баллы ИИ не вычисляет. Проверка подтверждает происхождение цитаты, но не заменяет проверку её смысла человеком перед публикацией. Для анализа отрасль помогает задать вопросы, но не служит источником фактов о задаче.

Каждая попытка записывается в `data/db.json → aiLogs`, включая неудачи и локальный ответ. `debug` в API относится к итоговому провайдеру; всю цепочку можно раскрыть в `AiDebugPanel` на `/business/new` после обновления страницы. Общий префикс `id` связывает попытки одного запроса. Значения настроенных API-ключей маскируются в журнале. Ошибка сохранения журнала возвращает HTTP 500 и не запускает дополнительный внешний запрос.

Для быстрой проверки без ключей:

```bash
curl -sS http://localhost:3000/api/ai/analyze \
  -H 'Content-Type: application/json' \
  -d '{"draftText":"Клиенты стали реже возвращаться, хотим понять почему","industry":"Общепит"}'

curl -sS http://localhost:3000/api/ai/build-card \
  -H 'Content-Type: application/json' \
  -d '{"draftText":"Данные: Есть CSV с 1200 заказами за 6 месяцев","answers":[{"questionId":"q-result","field":"expectedResult","answer":"Нужен дашборд повторных покупок"}]}'
```

## Как проверить каркас

1. Запустите проект без `.env.local` и откройте все семь страниц через навигацию.
2. Переключите роль на команду и обновите страницу: выбор должен сохраниться в cookie.
3. Откройте `/api/tasks` и `/api/teams`: должны возвращаться данные seed.
4. Выполните примеры AI API выше. Без ключей ожидаются 3–6 вопросов, поля с точными цитатами и debug с `provider: "local"`. Обновите `/business/new` и раскройте «Как работает ИИ».
5. Отправьте пустой JSON в этот endpoint: ожидается HTTP 400 с полем `error`.
6. Запустите `npm test`: проверяются формула, границы, подтверждения, seed, параллельная запись и сохранность повреждённой базы, evidence, приоритет вопросов, таймауты, повторы, fallback и ответы API. Внешние вызовы в тестах заменены моками; тесты не используют ключи, сеть или рабочую базу.
7. Для возврата к демо-данным выполните `npm run reset`: локальная база должна совпасть с seed.

Полный бизнес-сценарий из `AGENTS.md` станет доступен после следующего этапа разработки. Развёрнутой версии пока нет.

## Совместная работа

Разработчик A: `lib/**`, `app/api/**`, `data/**`, тесты. Разработчик B: страницы, компоненты и стили. `lib/types.ts` менять только по согласованию. Перед коммитом — `npm run lint && npm test`. Перед push — `git pull --rebase`, когда будет подключён выданный платформой командный репозиторий.
